# Obrist

Obrist is a DSL and abstraction layer for quickly writing documentation focused evals on top of harbor.

It provides a Pydantic-validated Python DSL for declaring benchmark
collections, suites, jobs, tasks, docs inputs, sandbox policy, and graders, then
compiles those definitions into disposable Harbor workspaces.

Harbor is the runtime. Harbor-specific behavior is still isolated under
`obrist.backends.harbor`, so benchmark collections such as `tempobench` and the
future `mppbench` can stay runtime read-only while Obrist owns only Harbor task
workspace emission.

## Package Boundaries

- `obrist.dsl`: public typed models used by benchmark collections.
- `obrist.collections`: reusable collection builders for config-driven benchmark
  jobs and packaged benchmark assets.
- `obrist.compiler`: Harbor compile helpers, generated-file headers,
  path guards, and compile result models.
- `obrist.backends.harbor`: Harbor task/job emission.

Only `obrist.backends.harbor` may import Harbor APIs or shell out to Harbor.

## Runtime Model

Benchmark collections are source packages. Obrist reads them and writes generated
runtime artifacts elsewhere:

```text
tempobench definitions
        -> obrist compiler
        -> .generated/obrist/<collection-suite>/
        -> Harbor
```

Generated text files that support comments receive this header:

```text
AUTO-GENERATED by Obrist. Do not edit directly.
```

Strict JSON files remain valid JSON and carry generated metadata inside the JSON
payload instead.

Harbor workspaces are generated at compile time, not build time. The Harbor
templates are source files packaged with `obrist`; rendering those templates
produces `.generated/obrist/**` artifacts.

## Collection Discovery

Collections can be loaded three ways:

- package entry points in the `obrist.collections` group
- explicit in-process registration with `obrist.register(name, factory)`
- import fallback through `<name>.collections.get_collection` or
  `datasets.<name>.collections.get_collection`

The public API is intentionally small:

```python
import obrist

collection = obrist.load("tempobench")
compiled = obrist.compile(collection, suite="default")
print(compiled.root)
```

`tempobench` defines a single `BenchmarkJobSpec`; Obrist expands that spec into
Harbor task directories, prompts, criteria, copied local solution directories,
dataset entries, and job config at compile time.

## Development

Use `uv` for Python commands:

```bash
uv run obrist compile tempobench
uv run ruff format --check obrist datasets tests
uv run ruff check obrist datasets tests
uv run --group dev mypy obrist datasets tests
```

Python code in `obrist` is typed and ships a `py.typed` marker.
Style follows PEP 8 and the Google Python Style Guide in spirit, with Ruff as
the enforcing formatter/linter.
